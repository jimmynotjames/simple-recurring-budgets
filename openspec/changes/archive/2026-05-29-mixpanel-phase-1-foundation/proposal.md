## Why

F-8.02 ("Mixpanel Phase 1 — foundation and basic stats") in [`docs/product-features-planning.md`](../../../docs/product-features-planning.md) is **Open**. The repo carries scaffolding from a prior partial wiring that violates the canonical contract in [`docs/analytics-spec.md`](../../../docs/analytics-spec.md): `MixpanelAnalyticsClient.swift` calls `Mixpanel.initialize(...)` synchronously inside `init` (so every launch — including opted-out launches in strict-opt-in jurisdictions — creates a `MixpanelInstance` and opens a flush channel, violating the lazy-init contract in §2.1.8 / §8 / §16.1); `simple_recurring_budgetsApp.init()` hard-codes `isOptedIn: { false }` so no event ever fires; there is no `AppSettings.analyticsOptIn` toggle, no `AppSettings.analyticsDistinctId`, no `ConsentJurisdiction` helper, no Settings UI, and no first-run consent sheet. F-8.01 (`oslog-diagnostic-logging`) shipped first to establish the OSLog↔`AnalyticsClient` boundary; this change ships F-8.02 against that boundary.

After this change ships, F-8.02 flips to **Implemented** and Phase 1 dashboards (built in Mixpanel per [`docs/analytics-spec.md` §11](../../../docs/analytics-spec.md#11-phase-1-dashboards)) can answer the Phase 1 product questions in [`docs/analytics-spec.md` §3](../../../docs/analytics-spec.md#3-product-questions--phase-1).

## What Changes

- **`AppSettings` extensions.**
  - Add `analyticsOptIn: Bool`, persisted under key `"analyticsOptIn"`. Default value is **locale-aware**, resolved on first read by `ConsentJurisdiction`: `false` in strict-opt-in jurisdictions, `true` in auto-opt-in jurisdictions.
  - Add `analyticsDistinctId: String`, persisted under key `"analyticsDistinctId"`. Generated as a `UUIDv4` on first read if absent and persisted; subsequent reads return the same value. Setter is internal — not exposed publicly.
  - Wire both keys into the existing `didChangeExternallyNotification` reload path so a value written from another iCloud-paired device is reflected here.
- **`ConsentJurisdiction` helper.** Pure function from `Locale.Region?` (or `String?` region identifier) to a `JurisdictionKind` enum (`required` / `auto_optin`). The strict-opt-in region table from [`docs/analytics-spec.md` §7.2](../../../docs/analytics-spec.md#72-strict-opt-in-jurisdictions-and-the-first-run-consent-sheet) lives in source code, mirrored from the spec; expanding or trimming the table is a one-line edit.
- **`MixpanelAnalyticsClient` refactor — lazy SDK init.** Defer `Mixpanel.initialize(token:trackAutomaticEvents:)` until the first opted-in `track`/`identify` call. Use a thread-safe one-shot init guard so concurrent first-call `track`s don't race the init. `reset()` clears the local SDK state AND resets the init guard so a subsequent toggle-on after a toggle-off re-initializes cleanly. Constructor takes `(token, isOptedIn, distinctIdProvider)`. On first init, register the `§10.2` super properties (including the explicitly-registered `bundle_id`) and set baseline people properties from `§10.3`. `trackAutomaticEvents: false` is preserved.
- **App-entry wiring.** Replace the hard-coded `isOptedIn: { false }` in `simple_recurring_budgetsApp.init()` with `{ [settings] in settings.analyticsOptIn }`. Pass `AppSettings.analyticsDistinctId` as the `distinctIdProvider`. The `#if DEBUG` token branch (dev project) / `#else` (prod project) stays in source per [`docs/analytics-spec.md` §16](../../../docs/analytics-spec.md#16-build-hygiene); tokens are NOT moved to `xcconfig` / `Info.plist`. The existing `analytics.track(AnalyticsEvent.appOpened)` call in `body`'s `.task` is preserved (the `appLaunched` → `appOpened` rename was already completed by a precursor change).
- **Settings — "Diagnostics & Analytics" section.** Adds a new section to `SettingsView` (between "iCloud Sync Status" and "Support" per existing section ordering) with: a single toggle bound to `AppSettings.analyticsOptIn`; a localized footer disclosing what is and is not sent (mirrors `§5`) and a one-line note that the initial state was set automatically based on the device locale. All copy keyed in `Localizable.xcstrings` per F-3.03.
- **First-run consent sheet (strict-opt-in jurisdictions only).** A one-time `Sheet` route on `Router` (or equivalent) presented immediately after the first successful `budget_created`, only when `ConsentJurisdiction.kind == .required` AND `analyticsOptIn` has not been explicitly set. The sheet has accept (flips opt-in to `true`) and decline (keeps opt-in `false` and dismisses permanently) actions. Per [`docs/analytics-spec.md` §7.2](../../../docs/analytics-spec.md#72-strict-opt-in-jurisdictions-and-the-first-run-consent-sheet) **no retroactive event replay** — `app_opened` and the triggering `budget_created` are NOT replayed when consent is granted.
- **Phase 1 events.** Add the canonical event constants from `§9` (`budget_created`, `budget_edited`, `budget_deleted`, `budget_reset`, `carry_over_reset`, `expense_logged`, `expense_edited`, `expense_deleted`, `settings_opened`, `setting_changed`, `analytics_consent_changed`) to `AnalyticsEvent`. Add a typo-safe `AnalyticsProperty` enum for `§10.1` keys.
- **Phase 1 instrumentation call sites.** One call site per event at the canonical site listed in `§9` / `§16.1` (Add/Edit Budget save, AddEditBudgetViewModel destructive paths, Add Expense save, Edit Expense save, swipe-delete, Reset Budget, Reset Carry-Over, Settings sheet present, settings transitions, consent toggle). Each call carries only the `§10.1` allow-listed properties; **no `ExpenseItem` field is transmitted by value.**
- **Phase 1 super properties.** `§10.2` registered on `MixpanelAnalyticsClient` first init: `app_version`, `app_build`, `device_class` (`phone` / `pad` / `mac`), `locale`, `region`, `week_start_day`, `currency_display_preference`, `icloud_state`, `budgets_count_bucket`, `carry_over_default_enabled`, `consent_jurisdiction`, `bundle_id` (explicit `registerSuperProperties` per `§11` fork-pollution defense). The mutable ones (`week_start_day`, `currency_display_preference`, `icloud_state`, `budgets_count_bucket`, `carry_over_default_enabled`) are refreshed when the underlying value changes.
- **Phase 1 people properties.** `§10.3` set on `identify` and refreshed on the relevant events: `first_seen_at`, `analytics_opt_in_at`, `budgets_count_bucket`, `default_currency_code`, `last_app_open_at`, `dominant_period`, `uses_carry_over`, `has_disabled_carry_over`, `budgets_with_carry_over_on_count_bucket`.
- **Tests.** Land the ten Swift Testing contracts from [`docs/analytics-spec.md` §18.1](../../../docs/analytics-spec.md#181-concrete-unit-test-contracts-phase-1): `ConsentJurisdiction` parameterized resolution; `AppSettings.analyticsOptIn` defaults; `AppSettings.analyticsDistinctId` UUID generation/persistence; lazy-init invariant; toggle-off ordering; toggle-on ordering (strict-opt-in); `app_opened` constant; PII enforcement at `expense_*` call sites; super-property attachment + bucket transitions; DEBUG/Release token literal branch.
- **Doc updates.** Per [`docs/analytics-spec.md` §19](../../../docs/analytics-spec.md#19-doc-updates-required-at-implementation-time):
  - `docs/tech-design-doc.md` §4.5 — add `"analyticsOptIn"` and `"analyticsDistinctId"` rows to the KV-key table.
  - `docs/tech-design-doc.md` §7 — confirm vendor named, opt-in toggle wired, lazy-init refactor complete (§7 already references the analytics-spec; minor refresh only).
  - `docs/tech-design-doc.md` §9 — refresh Future Technical Considerations row for analytics; add Phase 2 row pointing at F-8.03.
  - `docs/analytics-spec.md` §16.1 — flip the "Implementation starting state" subsection to a historical record (refactor complete).
  - `docs/analytics-spec.md` §19 — mark the F-8.02 rows as done.
  - `docs/product-features-planning.md` F-8.02 — flip status to **Implemented. Implemented by change `mixpanel-phase-1-foundation`.**
- **Out of scope (deferred or external).** Phase 1 dashboards in Mixpanel (configuration, not code; they ship as a tracked task alongside or shortly after the implementing change per F-8.02 Edge Cases). Token sourcing via `xcconfig` / `Info.plist` (explicitly forbidden by `§16` and F-8.02 Edge Cases). Identity aliasing across delayed `NSUbiquitousKeyValueStore` syncs (deferred to Phase 2 per `§6` limitations). ATT prompt and `AppTrackingTransparency.framework` integration (out of scope per `§16`). Phase 2 events / properties / experimentation seam (F-8.03).

## Capabilities

### New Capabilities

- `product-analytics`: Owns the product-analytics surface end-to-end — the `AnalyticsClient` protocol shape, the canonical event/property name catalog (`AnalyticsEvent`, `AnalyticsProperty`), the `MixpanelAnalyticsClient` lazy-init contract, the `ConsentJurisdiction` helper and its strict-opt-in region table, the consent flow (Settings toggle and first-run consent sheet rules), the no-PII / accepted-risk field-level allow/deny list (mirrored from `docs/analytics-spec.md §5`), the Phase 1 events (`§9`), per-event properties (`§10.1`), super properties (`§10.2`), people properties (`§10.3`), the launch-and-consent-transition ordering (`§8.1`), and the structural boundary with `AnalyticsClient` already established by `diagnostic-logging`. This capability is the single source of truth for "what we send to Mixpanel, when, with what consent, and at what privacy level." Future Phase 2 work (F-8.03) lands as a delta against this capability.

### Modified Capabilities

- `app-settings`: Add `analyticsOptIn: Bool` and `analyticsDistinctId: String` properties (with their KV keys, defaults, and external-change handling), and the `analyticsOptInKey` / `analyticsDistinctIdKey` static key constants. Add the `Key constants` requirement update so the key list reflects the two new keys. The `AppSettings` class, `KeyValueStore` protocol, and external-change observation requirements are not changed.
- `settings-screen`: Add a new "Diagnostics & Analytics" section requirement: a toggle bound to `AppSettings.analyticsOptIn` plus a localized footer with the §5 disclosure summary and the locale-default note. The existing sections (Budgets, Calendar, Display, iCloud Sync, Support, About) and the Done dismissal are not changed. The "No new ViewModel" requirement is preserved — the consent sheet's presentation is gated by view-local `@State` plus an `AppSettings` read; no `SettingsViewModel` is introduced.

The existing `add-edit-budget-screen`, `add-edit-expense-screen`, `budget-detail-screen`, and `budgets-screen` capability specs are NOT modified. The new event-emission call sites inside those views are diagnostic side-effects owned by `product-analytics` (mirroring how `diagnostic-logging` owns the `Logger.ui.debug` lines without modifying screen specs); nothing user-observable changes in those screens.

- **Code (refactor / new):**
  - `simple-recurring-budgets/Logging/MixpanelAnalyticsClient.swift` — refactor: lazy SDK init with one-shot guard, super-property registration, people-property setters, `reset()` resets the init guard, constructor accepts `distinctIdProvider`.
  - `simple-recurring-budgets/Logging/AnalyticsClient.swift` — extend `AnalyticsEvent` with the Phase 1 event constants from `§9`; add `AnalyticsProperty` enum for `§10.1` keys.
  - `simple-recurring-budgets/Settings/ConsentJurisdiction.swift` (new) — `JurisdictionKind` enum and pure resolver function with the `§7.2` region table.
  - `simple-recurring-budgets/Settings/AppSettings.swift` — add `analyticsOptIn`, `analyticsDistinctId`, the two key constants, and external-change reload entries.
  - `simple-recurring-budgets/App/simple_recurring_budgetsApp.swift` — wire `isOptedIn` to `AppSettings.analyticsOptIn`; pass `analyticsDistinctId` provider; preserve the existing `#if DEBUG` token branch and the `appOpened` `.task` call.
  - `simple-recurring-budgets/Views/SettingsView.swift` — add the Diagnostics & Analytics section.
  - `simple-recurring-budgets/Views/Consent/AnalyticsConsentSheet.swift` (new) — first-run consent sheet view.
  - `simple-recurring-budgets/Views/Routing/Router.swift` — add a `.analyticsConsent` sheet route (or equivalent existing sheet enum case) for the consent sheet.
  - Call-site edits in `AddEditBudgetView`/`AddEditBudgetViewModel`, `AddEditExpenseView`/`AddEditExpenseViewModel`, `BudgetDetailView`, `BudgetDetailView+ExpenseSection`, `SettingsView` — one canonical `analytics.track(...)` call per `§9` event at the canonical site (NEVER nested or derived from a `Logger.*` callback).
- **Code (tests):** new Swift Testing suites under `simple-recurring-budgetsTests/Logging/` (covering `§18.1` items 1–10) and `simple-recurring-budgetsTests/Settings/` (covering `analyticsOptIn` and `analyticsDistinctId` defaults / persistence). Existing `SpyAnalyticsClient` is extended with super-property and people-property recording so call-site tests can assert attachment.
- **Localizable.xcstrings:** new keys for the Settings section header / toggle title / footer body, and the consent sheet title / body / accept / decline buttons. All keys carry a translator-friendly `comment:`.
- **Docs:** update `docs/tech-design-doc.md` §§4.5 and 7 (and §9 future-work table), `docs/analytics-spec.md` §§16.1 and 19, `docs/product-features-planning.md` F-8.02 status. The `docs/main-prd.md` and `docs/ux-design-brief.md` files are NOT touched (no global product or UX rule moves).
- **Dependencies:** `mixpanel-swift` is already an SPM dependency in `simple-recurring-budgets.xcodeproj`. No package adds.
- **Performance:** Lazy SDK init means an opted-out launch in a strict-opt-in jurisdiction continues to incur zero Mixpanel cost (the current bug is the opposite). Auto-opt-in launches cost exactly one `Mixpanel.initialize` call, deferred to first track. Phase 1 events are user-initiated and low-frequency; no client-side sampling is required (`§16`).
- **Privacy / security:** No PII transmitted. The accepted-risk fields (`budget_name`, `budget_allocation_amount`) are explicitly limited to `budget_*` events per `§5.4`. `ExpenseItem` fields are hard-banned. `bundle_id` super-property is registered explicitly to enable the `§11` universal project filter. The locale-aware consent default complies with `docs/main-prd.md` §6.3 and the [`docs/tech-design-doc.md` §7](../../../docs/tech-design-doc.md) privacy contract.
- **Boundary with F-8.01:** preserved. No call site under `simple-recurring-budgets/` invokes `Logger.*` and `AnalyticsClient.track(...)` for the same conceptual event with the intent of cross-routing. The structural test in `diagnostic-logging` continues to pass.
